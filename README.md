# Flotex EGP — نسخة هاتف مستقلة داخل Manus

هذا مشروع Expo Router وReact Native مستقل عن أرشيف المصدر المرفق. احتُفظ بالواجهات والأصول الأصلية، وأُنشئت له قاعدة بيانات مستقلة؛ لم يتضمن الأرشيف بيانات العملاء أو أرصدتهم السابقة. توجد نسخة تاريخية من وصف الأرشيف في `docs/source-archive-README.md` ولا تُعد دليلًا على حالة هذه النسخة.

## فتح المشروع ومعاينة الهاتف

افتح مشروع **Flotex EGP - نسخة مستقلة** من مساحة Manus، واستخدم Preview لعرضه وتحرير شيفرته. لمعاينة الهاتف، استخدم **Connect Expo** من لوحة المشروع، وثبّت **Expo Go** على الهاتف وسجّل الدخول بحساب Expo نفسه إن طُلب منك ذلك، ثم امسح رمز QR المعروض. تحقق الهاتف الفعلي مرتبط بتوصيل جهاز المستخدم ولم يُنجَز تلقائيًا.

معاينة Expo Go ليست ملف تثبيت مستقلًا. لم يُنشأ ملف APK/AAB أو إصدار iOS، ولم يُنشر المشروع للعامة. لبناء نسخة تثبيت قابلة للتوزيع، استخدم **Build** في لوحة المشروع بعد إعداد خدمة API مستقرة وآمنة للإصدار وإكمال إعدادات Expo والتوقيع. لا تستخدم عنوان المعاينة المؤقت كعنوان نهائي للإصدار.

## الحسابات الإدارية

داخل لوحة التحكم يوجد قسم «إنشاء الحسابات» لإنشاء حساب باسم وبريد وهاتف وتاريخ ميلاد ومحافظة وكلمة مرور. لا تُرسل رسالة تحقق عند إنشائه بواسطة الإدارة. بعد صحة بيانات الدخول الأولى، يلزم تعيين كلمة مرور جديدة قبل الحصول على جلسة دخول، وتُعرض حالة الحساب وتوقيت أول دخول مع سجل للعمليات. يجب تسليم كلمة المرور المبدئية بطريقة آمنة؛ الإنشاء بلا رمز بريد لا يثبت ملكية عنوان البريد. قواعد الدخول والعمليات الأخرى تظل كما في التطبيق، ولا يمثل ذلك تحققًا ماليًا إضافيًا.

## التحكم في مواضع الأزرار — نطاق جزئي

تدعم لوحة التحكم سحب اختصارات الخدمات باللمس أو الفأرة في مساحتي **الرئيسية والمحفظة**، مع معاينة وحفظ واستعادة الإعدادات الافتراضية وسجل تدقيق. يحفظ الخادم المواضع في قاعدة البيانات ويطبقها على الواجهة. لا يشمل التنفيذ الحالي أزرار النماذج والتأكيدات وبقية صفحات التطبيق، ولا يسمح بنقل الأزرار عبر الشاشة كاملة أو من صفحة لأخرى. قد تعود إعدادات الترتيب الفردية السابقة بعد إعادة الضبط. لهذا لا تكتمل بعد مطالبة المستخدم بجميع أزرار التطبيق. عند تخصيص المواضع، ينتقل زر الدعم من ترويسة الشاشة إلى مساحة الاختصارات.

## البريد والبيانات والسلامة

بريد الإدارة مضبوط على `dyblhwyty@gmail.com`، وكلمة مرور تطبيق Gmail محفوظة في مخزن أسرار Manus تحت الاسم `AUTH_OTP_APP_PASSWORD` ولا تحفظ في ملفات المشروع. نجح التحقق من اتصال SMTP دون إرسال رسالة. كلمة مرور البريد ليست كلمة مرور الدخول لحساب التطبيق؛ يلزم إنشاء حساب الإدارة بالطريقة الموجودة في التطبيق.

ترحيلات 0055 و0056 طُبقت على قاعدة هذه النسخة بعد التأكد أنها فارغة. لا تطبق ترحيلات الأرشيف على قاعدة عملاء أو أموال قائمة دون نسخة احتياطية قابلة للاستعادة ومراجعة SQL وخطة رجوع: الترحيل `0005` القديم يحتوي على تحديث يصفر أرصدة، وحارس الترحيل الآمن لا يغني عن المراجعة. قاعدة تطوير Manus وقاعدة الإصدار المنشور مشتركتان. لم تُنفذ معاملات مالية أو رسائل فعلية أثناء التحقق.

لا تشغّل اختبارات قاعدة البيانات على قاعدة Manus. يمنع إعداد Vitest تشغيل الاختبارات ضد قاعدة غير محلية؛ للاختبارات المتكاملة أنشئ قاعدة معزولة على `127.0.0.1` باسم يبدأ بـ `flotex_test_` واتبع محددات كل اختبار. تشغيل اختبارات الوحدة دون قاعدة يتطلب إزالة `DATABASE_URL` من بيئة الاختبار، مع استبعاد الملفات المعتمدة على قاعدة بيانات وتوفير قيم تجريبية غير حقيقية عند الحاجة.

اجتازت اختبارات الحسابات الجديدة ومواضع الأزرار اختبارات تكامل محلية، كما اجتاز التسجيل والتحويلات والدفتر المالي 32 اختبارًا على قاعدة تجريبية معزولة. نجح فحص TypeScript وبناء الويب وتجميع JavaScript الخاص بـ Android. لم ينجح إنشاء Hermes bytecode في بيئة الفحص لأن مترجم Hermes المرفق لمعمارية x86 بينما البيئة الحالية ARM؛ لذلك لا يُعد تجميع JavaScript اختبارًا مكتملًا لبناء APK.

```bash
pnpm dev        # Metro على 8081 وAPI على 3000
pnpm check      # فحص TypeScript
pnpm build      # تصدير الويب وتجميع الخادم، وليس APK
pnpm db:migrate # بعد مراجعة الترحيلات والتأكد من سلامة قاعدة البيانات
```

`app/` للشاشات، `components/` للمكونات، `server/` للخادم، `shared/` للمنطق المشترك، `drizzle/` للمخطط والترحيلات، و`tests/` للاختبارات. توجد قائمة العمل والحالات المتبقية في `TODO.md`.
