# تقرير تسليم نسخة Flotex EGP المستقرة

- **اسم المشروع:** Flotex EGP — نسخة مستقلة
- **نوع المشروع:** تطبيق هاتف Expo / React Native مع خادم API وقاعدة بيانات Manus
- **رابط الاستخدام على الهاتف:** https://flotexegp-m3sdsehb.manus.space
- **مسار المعاينة الأصلية داخل Manus:** معاينة المشروع من لوحة المشروع، أو Expo Go عبر رابط المعاينة الخاص بالمشروع.
- **المشروع الأصلي:** لم يُعدّل؛ العمل جرى على نسخة مستقلة جديدة داخل مساحة Manus.

## الإضافات المنفذة

### 1. شحن الألعاب

- قسم كامل للعميل: قائمة الألعاب، الباقات الجاهزة، الكمية المخصصة، خانات بيانات اللاعب التي يحددها المدير، ملخص السعر، وسجل الطلبات.
- قسم كامل للإدارة: إدارة الألعاب والباقات، الصور، الأسعار، تفعيل/إيقاف الخدمة، مراجعة الطلبات، الاعتماد والخصم، الرفض والإلغاء، ومتابعة التنفيذ حتى إكمال الشحن بمرجع المزود.
- حجز المبلغ من الرصيد المتاح عند إرسال الطلب، ثم خصمه نهائيًا مرة واحدة عند الاعتماد، مع تحرير الحجز عند الرفض أو الإلغاء.
- منع تكرار العملية بمرجع عملية (Idempotency) وبصمة للبيانات.
- رسوم خدمة قابلة للضبط من لوحة الإدارة، تُعرض منفصلة قبل التأكيد وتُضاف لمحفظة تمويل شحن الألعاب عند الاعتماد.
- محفظة تمويل مستقلة للخدمة مع سجل حركات وتمويل إداري موثق.
- إشعارات للعميل عند استلام الطلب واعتماده ورفضه وتنفيذه وإكماله.

### 2. تطوير واجهة الإدخار

- إعادة تصميم شاشة الإدخار بهوية بصرية أكثر احترافية: بطاقة رصيد بارزة، بطاقات خطط واضحة، اختيار سريع للمبالغ، ملخص تفصيلي للعائد والرسوم والصافي التقديري، وشريط إجراء ثابت.
- إظهار الحد الأدنى والحد الأقصى والرسوم والعائد المتوقع بوضوح قبل الإرسال.
- في التحديث الأخير، يظهر العائد المتوقع مباشرة أسفل حقل المبلغ ويتحدث أثناء الكتابة، مع تقريب العرض إلى منزلتين فقط دون تغيير دقة الحساب؛ تُفتح لوحة أرقام عشرية وتُحجز مساحة مناسبة كي لا تغطي لوحة المفاتيح ملخص العائد.
- الحفاظ على منطق الادخار الحالي: مراجعة إدارية، حجز مؤقت، استحقاق العائد، وإلغاء/استرداد وفق قواعد الخدمة.

### 3. تحسينات الاتساق والاستقرار

- إصلاح تكرار لاحقة العملة في شاشات شحن الألعاب ولوحة الإدارة.
- إصلاح عدّاد البحث الإداري عند ربط جداول الطلبات بالألعاب.
- السماح بأسعار وحدات بأربع منازل عشرية في الكمية المخصصة.
- إعادة ضبط مفتاح عملية تمويل المحفظة بعد نجاحها لمنع رفض التمويل المتكرر بالخطأ.
- معالجة قفل قاعدة البيانات الذاتي في إنشاء طلب شحن الألعاب، وهو الخطأ الذي كان يترك الطلب معلقًا على «جارٍ الإرسال».
- التحقق من أن شاشات الإدخال محمية بلوحة المفاتيح، وأن نجاح التسجيل وتسجيل الدخول والخروج يعملان، دون تغيير تصميم المشروع الأصلي.

### 4. استمرار الجلسة بعد إغلاق التطبيق وإعادة تشغيل الهاتف

- استعادة رمز الجلسة وبيانات المستخدم المحفوظة قبل انتظار الخادم، فلا تتحول شاشة التحميل أو ضعف الإنترنت إلى تسجيل خروج.
- لا يُمسح الحساب المحلي عند خطأ الشبكة أو انقطاع الخادم المؤقت؛ يبقى المستخدم ظاهرًا ويعيد التطبيق المحاولة تلقائيًا.
- لا يُعتبر الحساب منتهيًا إلا عندما يرد الخادم بنجاح بأن الجلسة غير صالحة، أو عند تسجيل خروج صريح.
- تجديد نشاط الجلسة والجهاز من دون تدوير الرمز نفسه، لتجنب إبطال جلسة صالحة بسبب سباق تحديث.
- رسالة انتظار واضحة أثناء التحقق من الجلسة، وحماية مسارات الدخول من التوجيه قبل اكتمال استعادة الحالة.
- اختُبرت استعادة الجلسة عبر إعادة تحميل التطبيق، واختبارات وحدات للتمييز بين خطأ الشبكة والرد الفارغ الناجح وتسجيل الخروج الصريح.

### 5. خدمة 1xBet داخل خدمات الألعاب

- إضافة 1xBet إلى كتالوج الخدمات بصورة قابلة للتغيير من لوحة الإدارة، مع صفحة خدمة فيها تبويبا الإيداع والسحب.
- الإيداع: مبلغ الإيداع، ID المستخدم، رسوم إيداع تُضبط لكل خدمة، الإجمالي، وتأكيد الطلب مع حجز مؤقت للرصيد.
- السحب: المدينة والشارع نصّان ثابتان يحددهما المدير ولا يكتبهما العميل، ويُحفظ العنوان الظاهر داخل الطلب. يمكن تحديد نصّي المدينة والشارع وتعليمات السحب ونسخها مباشرةً دون أزرار نسخ. يحرر المدير نص «كيفية السحب» كاملًا متعدد الأسطر ويحفظه، وتعيد صفحة الإرشادات جلب أحدث نص عند فتحها/العودة إليها وتزامنه تلقائيًا دون تحديث التطبيق.
- حد أدنى افتراضي مستقل للإيداع 50 ج.م وللسحب 50 ج.م، قابل لكل منهما للتعديل بالزيادة أو النقصان من لوحة الإدارة؛ يُطبّق فورًا على الطلبات الجديدة ويُتحقق منه على الخادم أيضًا.
- طلب السحب لا يخصم من محفظة Flotex ولا يحجز رصيدها؛ يظل طلبًا للمراجعة والتنفيذ الإداري. لا يدّعي التطبيق اتصالًا مباشرًا بمزود 1xBet أو تنفيذًا خارجيًا تلقائيًا.
- سجل كامل للطلبات والحالات، مرجع المزود عند التنفيذ، ملاحظات الإدارة، وإشعارات العميل والإدارة.

### 6. أحدث العمليات والطلبات في لوحة الإدارة

- مصدر موحّد من الخادم يجمع طلبات الإيداع والسحب، تحويلات الأموال، الادخار، خدمات الألعاب و1xBet، الذهب، الكوين، المعاملات الخارجية، توثيق الحساب، تغيير الهاتف وتوثيق الهاتف.
- ترتيب زمني تنازلي مع اسم العميل ورقم الحساب ونوع العملية والمبلغ أو توضيح عدم وجود مبلغ ثابت، والمرجع والحالة ووقت الإنشاء؛ يعرض وقت آخر قرار عند توفره.
- تحديث تلقائي كل 7 ثوانٍ دون زر تحديث يدوي، وإبطال فوري لذاكرة الاستعلامات بعد المراجعة. تعرض الواجهة أحدث 100 عملية، ويمكن فتح سجل الخدمة التفصيلي للوصول إلى الأرشيف الأقدم.
- الطلب المعتمد أو المرفوض أو المنفذ/الملغي يخرج من «المعلقة» بعد قرار الخادم، ولا يعود إلى قائمة المراجعة؛ تبقى حالته ووقت القرار في سجل العمليات والأرشيف الخاص بالخدمة.
- مركز «طلبات المستخدمين» يستخدم المصدر نفسه للطلبات المعلقة ويشمل أنواع الخدمات والتحقق، مع إبقاء رسائل الدعم غير المقروءة ضمن مسار منفصل.
- عند إضافة خدمة جديدة، تُربط مرة واحدة بمصدر العمليات الموحد؛ بعد ذلك تدخل الطلبات تلقائيًا في الفرز والتحديث دون إجراء يدوي من مدير النظام.
