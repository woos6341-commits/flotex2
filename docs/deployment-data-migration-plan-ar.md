# خطة عزل ونشر FLOTEX EGP — النسخة المستقلة

## حالة النسخة المنشورة

- أُنشئ مشروع **FLOTEX EGP — نسخة مستقلة** داخل Manus Mobile، ونُقلت الشيفرة والأصول والمخطط إليه. بقي ملف ZIP والمشروع المصدر دون تعديل.
- نُشرت النسخة المستقلة على عنوان النسخة المستقلة عند اعتماد النشر في Manus. يعرض عنوان الجذر شاشة الدخول، وأعاد `GET /api/ready` حالة HTTP 200 مع اتصال قاعدة البيانات.
- بيانات التشغيل ليست جزءًا من ZIP: لا حسابات عملاء أو جلسات أو أرصدة أو معاملات أو خطط ادخار نُقلت إلى النسخة الجديدة. مخطط قاعدة المشروع الجديدة مهيأ، وكانت خالية من حسابات المستخدمين والخطط عند النشر.
- هوية Android/iOS الجديدة ومعرف Manus خاصان بالمشروع المستقل؛ عنوان API الإنتاجي على النطاق المستقل ذاته، ولا يعود إلى الأصل. عنوان Preview يظل ديناميكيًا من Manus.
- بريد الإدارة المعتمد في الشيفرة هو `dyblhwyty@gmail.com`. اعتماد Gmail ومفتاح تشفير وثائق الهوية محفوظان في Secrets المحمية فقط. لا تُرسل رسائل اختبار ولا تُدرج القيم السرية في Git أو Native bundle.
- معاينة الويب العامة متاحة. لم يُوصل جهاز Expo Go ولم يُنشأ APK/AAB بعد؛ يلزم استخدام لوحة المشروع وربط Expo لإنشاء ملف تثبيت.

## عدم نقل البيانات

قبل أي استيراد مستقبلي يلزم مصدر قاعدة متسق ومصرح به، نسخة احتياطية قابلة للاستعادة، مراجعة الترحيلات، وبيئة staging منفصلة. لا تُرسل DSN أو نسخة قاعدة العملاء أو مفاتيح التشفير عبر المحادثة. لا تُنسخ جلسات/OTP أو رموز الأجهزة. لا تُنقل محافظ أو خطط/دفعات مالية جزئيًا؛ إذا أُجيز النقل مستقبلًا، يلزم التحقق من الدفاتر والحجوزات والمراجع ومفاتيح idempotency لكل عملة وخطة. لا يُشغل دفع أرباح خلال الاستيراد أو المطابقة.

مخطط SQL في `drizzle/` هو جزء من الشيفرة وليس نسخة بيانات. الترحيل المطبق يخص قاعدة المشروع الجديد فقط؛ لا تُعِد تشغيل SQL يدويًا على قاعدة المصدر. قاعدة Manus الخاصة بالمشروع مشتركة بين تطويره ونشره، لذلك لا تُجر اختبارات كتابة أو حذف عليها.

## الجدولة المالية

مسار المهمة المعتمد هو Manus Heartbeat `POST /api/scheduled/savings-auto-payout` كل دقيقة، لا خدمة Cron خارجية. يسجل التطبيق المهمة تلقائيًا في الإنتاج عند اعتماد خطة ادخار نشطة، ويتحقق من هوية callback ومعرف المهمة. يعالج العوائد عند أول فحص بعد خمس دقائق من `nextPayoutAt` إذا لم يسجل المدير دفعة؛ يمنع القيد الذري التكرار ويفحص التمويل. تعذر تسجيل المهمة مؤقتًا يؤدي إلى محاولات backoff تلقائية (5 ثوانٍ، 15 ثانية، دقيقة، ثم كل 5 دقائق)، وإعادة التحقق بعد تشغيل الخادم.

في وقت التحقق بعد النشر، كان عدد الحسابات والخطط النشطة صفرًا، وأعادت قائمة Manus Heartbeat لهذا المشروع صفر مهمة؛ لذلك لم تُنشأ مهمة فارغة ولم يحدث قيد عوائد. تُنشأ المهمة تلقائيًا بعد اعتماد أول خطة نشطة. المعالجة الحالية تقيد العائد في دفتر النسخة الجديدة فقط، ولا ترسل تحويلًا مصرفيًا أو إلى محفظة خارجية. الاستضافة `on_demand` وقد يوقظها الفحص كل دقيقة عند وجود خطة؛ التكلفة الفعلية تعتمد على سياسة حساب Manus.

## حزمة الهاتف

تشغّل Manus Expo/Metro على `8081` وAPI على `3000`. معاينة الويب داخل Manus متاحة، والرابط المنشور يصلح أيضًا لفتح واجهة الهاتف في المتصفح. يضبط مصدر Expo الآن fallback للإصدارات الأصلية على عنوان API المستقل المنشور، ولا يقبل عنوان Preview أو عنوان المصدر في إصدار الهاتف. استخدم Dashboard **Connect Expo** لمعاينة Expo Go بعد إعداد الاتصال ومزامنة البيئة. لم يُنشأ APK/AAB بعد؛ يتطلب بناؤه **Build Android → APK** من لوحة Manus وربط Expo إن طلبته اللوحة. لا تعلن عن إصدار قابل للتثبيت قبل نجاح عملية البناء. خصائص Android الأصلية، مثل الإشعارات والكاميرا وروابط التطبيقات، يلزم التحقق منها على جهاز فعلي؛ إعداد Push/Firebase منفصل عن المعاينة.

## فحوص التسليم وبوابات الإطلاق

1. شُغلت فحوص TypeScript وESLint وبناء Expo Web/API واختبارات Vitest على MariaDB محلية loopback معزولة وبيانات اصطناعية؛ لم تُرسل أموالًا أو بريدًا فعليًا.
2. تهيأ مخطط النسخة الجديدة فقط؛ لا توجد بيانات مستخدمين أو أرصدة مستوردة.
3. نشر API الإنتاجي واختبار readiness نجحا على مشروع Manus المستقل؛ لا يوجد Heartbeat مالي نشط قبل وجود خطة ادخار نشطة.
4. بناء APK/AAB من لوحة المشروع ما زال معلقًا؛ بعد البناء اختبر الدخول والتوثيق وتغيير الهاتف والإشعارات على جهاز اختبار.

لا تعني معاينة التطبيق أو إنشاء checkpoint أو نجاح `/api/health` نقل البيانات. يُحدد التشغيل المالي فقط بوجود خطة نشطة واستحقاق عائدها وفق القواعد المذكورة أعلاه.
